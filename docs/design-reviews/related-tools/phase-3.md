# 관련 계산기 추천 구현 및 로컬 검증

2026년 11월 22일 KST · `codex/related-tool-discovery` · 비교 기준은 당일 원격 `main`과 일치한 `ae79937`이다. 운영 사이트에서 조사한 [Phase 1 검토안](phase-1.md)을 이 브랜치에 구현했다. 아래 결과와 스크린샷은 로컬 Flask와 Chromium에서 얻었다.

## 무엇이 달라졌나

31종 도구의 6개 언어, 총 73개 URL에서 계산에 성공하면 결과와 기존 공유·내려받기 작업 뒤에 **이어서 계산하기**가 나타난다. 추천 수는 0~2개다. 한국어 양력 만나이 계산 뒤에는 연나이와 생일 D-day를, 음력인 경우에는 음력 생일과 연나이를 제시한다. 반려동물 환산표의 지원 범위를 벗어나면 해당 표를 추천하지 않는다.

- 홈에서는 취학 전·학령기 출생연도에 학년을, 나머지에는 생일을 먼저 제시한다. 기존 학년 링크는 목적지가 지원하는 출생연도만 전달한다. 해당 연도는 목적지에서 수정할 수 있다.
- 추천 영역의 실폭이 560px 이상이면 카드 두 개를 나란히 놓고 좁으면 세로로 쌓는다. 카드 전부가 키보드로 이동할 수 있는 링크다. 결과 낭독 영역과 추천 탐색 영역을 구분하고, 입력을 바꾸면 이전 추천을 숨긴다.
- 목적지 주소는 같은 언어의 공개 페이지 레지스트리에서 얻는다. 기존 연도 링크를 제외한 새 연결은 기본 URL을 쓴다. 생년월일 전체·가족 정보·기념일 이름은 추천 링크나 전환 표시에 넣지 않는다. 서버 계산 결과에서는 자바스크립트를 꺼도 링크를 따라갈 수 있다.

## 검증 결과

| 항목 | 로컬 결과 |
|---|---|
| 기존 기능·회귀 | Python unittest **643개**, Node 단위 테스트 **908개** 통과. 별도 Playwright로 다국어 계산 40개 흐름, 6개 언어별 날짜 가감·날짜 차이, 언어 메뉴 21개 페이지·화면 폭 조합, 가족 페이지 동의 상태 5종을 검사했다. |
| 추천 링크·언어 | 기본 URL 73개 모두 HTTP 200. 기본 추천은 같은 언어의 공개 도구로 직접 연결됐다. JS를 끈 Chromium에서 기본 페이지 73개와 경계값 결과 34개를 열었고, 보이는 추천 링크 46개에서 referrer 차단을 확인했다. 학년·학번 범위 밖의 연도는 기본 주소로 이동했다. |
| 실제 다음 계산 | 영어 날짜 차이 → 날짜 가감은 이동 뒤 유효한 입력을 제출해야 후속 완료 1건이 잡혔다. 한국어 만나이 → 연나이는 연도가 채워진 GET 결과만 보면 0건, 수정 후 제출하면 1건이었다. 일본어 학교연도 POST에서 일본어 카드가 나타났다. |
| 검색 응답 | 기본 73개와 예외 7개의 HTTP 상태·리디렉션·robots·제목·설명·canonical·hreflang·OG·JSON-LD를 원본과 비교해 일치했다. 사이트맵 인덱스 및 하위 6개의 위치 목록도 일치했다. |
| 접근성 | 4개 홈 폭에서 가로 넘침이 없었고, 카드 클릭 영역은 양쪽 모두 44px 이상이었다. Tab 이동·Enter 탐색, 이름이 있는 탐색 영역의 접근성 트리, 인쇄 시 추천 숨김을 확인했다. 포르투갈어 문구를 390px·글자 크기 200%로 확대한 상태에서 쿠키 배너가 카드를 가리는 문제를 발견해 배너 높이를 제한했다. 두 카드 접근과 키보드로 쿠키 거부를 재검증했다. |

한국어 반려동물 페이지에서 JS를 끄면 기존 폼의 ‘현재 나이’와 ‘입양일’ 입력 모드를 직접 열 수 없다. 이 두 모드의 서버 결과에 표시되는 추천은 검사했다. 접근성은 Chromium의 키보드 동작과 접근성 트리를 기준으로 검증했다. 실제 보조기기 음성 출력과 운영 광고 채움은 별도 관찰 대상이다.

### 모바일 로컬 성능

390×844, 제3자 요청 차단, CPU·네트워크 제한 없음, 새 Chromium 컨텍스트를 버전별 5회씩 번갈아 열었다. 수치는 홈의 중앙값이다.

| 항목 | 원본 | 카드 적용 |
|---|---:|---:|
| 입력 전 LCP | 68ms | 72ms |
| 입력 전 누적 레이아웃 이동 | 0.00011 | 0.00011 |
| 같은 출처 하위 리소스 본문 합계 | 2,277,765B | 2,294,322B |
| 제출 이벤트부터 두 번째 애니메이션 프레임까지 | 38.2ms | 40.5ms |

리소스 본문은 약 16.2KiB 늘었다. 제출 프레임 시간은 결과 표시의 로컬 진단값이다. 사용자 기기에서의 p75 INP·LCP·CLS는 운영 반영 후 필드 데이터로 확인해야 한다.

## GA4 측정 및 판독

| 이벤트 | 기록 시점과 중복 기준 |
|---|---|
| `calculator_completed` | 동의한 사용자가 유효한 계산을 실행할 때마다 1회. 결과 URL 직접 방문·새로고침은 제외한다. |
| `related_tool_impression` | 활성 탭에서 카드 면적의 절반 이상이 연속 1초 보이거나 먼저 활성화된 경우. 계산 한 번에 목적지별 1회다. |
| `related_tool_click` | 해당 결과 링크의 첫 활성화. 새 탭과 저장 차단은 클릭으로 집계하되 후속 완료율의 연결 가능한 클릭 분모에서 제외한다. |
| `related_calculator_completed` | 같은 탭·같은 언어에서 해당 도구를 연 뒤 30분 이내에 처음으로 직접 계산을 마친 경우. 표시를 한 번만 소비한다. |

카드 모드 분석 시나리오 12개와 기준선 모드의 홈 → 학년 시나리오가 통과했다. 실제 gtag 로더가 만드는 페이지뷰와 네 이벤트의 요청을 로컬 수신기에서 검사했다. 테스트용 쿼리·해시·가족 페이지 referrer에 넣은 입력값은 분석 요청에 포함되지 않았다. 자동 폼 이벤트의 목적지 주소도 확인했다. 실제 로더 검사에서만 브라우저 테스트 컨텍스트의 CSP 제한을 풀고 수집 주소를 루프백으로 바꿨다. 외부 DNS는 차단했다. 지연 로더, 동의 변경, 저장 차단, 직접 방문, 새 탭, 30분 만료, 다른 페이지 경유도 별도로 검증했다.

운영 적용이 승인되면 먼저 `RELATED_TOOLS_LAYOUT=baseline`으로 기존 링크를 28일 측정하고, 이어서 `RELATED_TOOLS_LAYOUT=cards`로 28일 측정한다. 기본값은 `cards`다. 두 기간은 `placement_version`으로 구분한다.

- **추천 CTR**은 목적지·언어·카드 위치별 첫 클릭 수를 노출 수로 나눈다. **완료 대비 다음 계산 실행률**은 후속 완료 수를 측정 가능한 목적지가 제시된 출발 완료 수로 나눈다. **이동 후 완료율**의 분모는 `measurable=true`인 추천 클릭이다.
- 한국어 생일 D-day처럼 도착지 추적이 꺼진 경로는 출발지에서 확인한 클릭까지만 보고한다. 기존 결과 링크가 없던 도구의 기준선 CTR은 ‘해당 없음’이다. 이 경우 같은 세션에서 다른 계산까지 완료한 비율을 보조 지표로 본다.
- 조회수/세션, 세션당 평균 참여 시간, 참여율은 언어·기기와 표본 수를 함께 확인한다. 검색 영향은 Search Console의 페이지별 노출·클릭·색인 상태로 본다. 이번 작업으로 운영 참여도나 순위의 변화를 측정한 것은 아니다.

### 재현

저장소의 Python 환경에서 `python -m unittest discover -s tests`, Node에서 `node --test tests/*.test.js`를 실행한다. Playwright 테스트에는 `AGECALC_TEST_BASE`로 로컬 Flask 주소를 지정한다. 브라우저 모듈 위치가 기본값과 다르면 `PLAYWRIGHT_MODULE`을 지정할 수 있다. 실제 gtag 요청까지 검사할 때는 `tests/related-tool-analytics.cjs`에 `GA_TEST_LOADER`로 로컬 로더 파일을 제공한다.

화면 재현은 같은 입력과 뷰포트를 쓰는 `tests/related-tools-browser.cjs`로 수행한다. 원본 서버에는 `SCREENSHOT_VARIANT=before`, 카드 서버에는 기본값을 쓰고 각각의 `SCREENSHOT_DIR`을 지정한다.
