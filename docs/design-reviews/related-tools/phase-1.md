## 1. 운영 기준선

공개 GET 요청으로 홈 간편 계산·선택형 조회표를 포함한 계산 진입점 31종의 언어별 기본 URL 73개를 확인했다. 한국어 27개, 영어 9개, 일본어 11개, 스페인어 8개, 브라질 포르투갈어 10개, 중국어 간체 8개 모두 리디렉션 없이 HTTP 200이었다. 운영 HTML이 지정한 버전 해시 34종이 main의 대응 CSS·JS와 일치했다. 이 해시 대조는 해당 정적 자산에 한정한다.

## 3. UI 대안과 선택

| 대안 | 넓은 화면 | 좁은 화면 | 선택 기준 |
|---|---|---|---|
| **A. 결과 아래 행동 카드 최대 2개** | 추천 영역 실폭 560px 이상이면 동일 폭 2열. 첫 카드는 제목 굵기와 링크 강조색으로 우선순위 표현 | 세로 1열. 카드 전체를 하나의 링크로 제공 | **채택.** 번역이 길어져도 다음 행동과 필요한 입력을 함께 읽을 수 있다. 기존 홈의 768px 결과 영역은 2열을 충분히 수용한다. |
| B. 대표 행동 링크와 작은 보조 링크 | 결과 요약 아래에 대표 링크 1개, 그 아래에 짧은 보조 링크 | 같은 순서로 수직 배치 | 높이는 줄지만, 작은 보조 링크와 기존 공유·다운로드 버튼의 역할이 덜 분명하다. |

결과 → 기존 공유·ICS·CSV·인쇄 → **이어서 계산하기** → 추천 → 설명·광고 순으로 구성한다. 카드 두 장을 채우기 위해 약한 추천을 추가하지 않는다. 홈은 기존 결과 박스 한 곳을 고치고, 글로벌 화면은 입력·결과 작업 영역 다음과 본문 설명 사이에 놓는다. 카드 간격 12px, 내부 여백 16px, 결과와 추천 간격 24px를 시작값으로 쓴다. 고정 높이·이미지·캐러셀 없이 기존 페이지의 색상과 글꼴을 사용한다.

CTA 예시는 ‘출생연도로 연나이 확인’, ‘월·일로 다음 생일 찾기’, ‘기준일에 일·주·개월 더하기’다. 설명은 필요한 입력과 새로 얻을 결과를 한 문장에 담는다. 제목이 목적지를 설명하는 실제 앵커 하나, 최소 44px 터치 영역, 보이는 포커스, 논리적인 Tab 순서를 적용한다. 추천은 결과 낭독 영역 밖에 두고 자동으로 포커스를 가져가지 않는다. 인쇄용 출력에는 카드가 들어가지 않게 한다.

## 4. 데이터 구조와 입력 재사용

- 기존 페이지 레지스트리를 경로·언어·공개 상태의 기준으로 삼는다. 매핑은 출발 도구별 우선순위 목록이며 각 항목은 목적지 키, 번역 문구 키, 선택적 조건으로 구성한다. 예를 들어 한국어 양력 만나이는 `annual_age_calculator`, `birthday_dday_calculator` 순이다. 조건은 표에 명시한 양·음력, 결과 모드, 목적지 지원 범위로 한정한다.
- Flask에서 현재 언어에 존재하는 목적지만 `localized_url()`로 해석한다. 자기 링크·중복·통합 전 경로를 제거하고 최대 2개를 반환한다. 같은 Jinja 부분 템플릿으로 SSR 링크를 출력한다. JS 계산기는 성공 시 해당 조합을 노출하고 초기화·오류 시 숨긴다. 기본 페이지의 기존 본문 및 도구 탐색은 JS 없이도 접근할 수 있게 한다.
- 사용자가 선택한 **최소 재사용**을 적용한다. 홈 → 학년, 만나이 → 연나이 등 검증된 연도 링크를 유지하고 도착지에서 입력을 고칠 수 있게 한다. 신규 링크에는 입력값이 없는 기본 URL을 사용한다. 날짜 전체, 생일 월일, 가족·기념일 이름의 쿼리·해시·저장소 전달과 자동 제출을 추가하지 않는다.
- 출발지와 도착지에서 계산 기준이 바뀌면 CTA에 밝힌다. 음력 생일에서 나온 **이번 양력 날짜**는 매년 반복되는 양력 생일로 해석하지 않는다. 학번에서 얻은 통상 출생연도를 확정 생년으로 표시하지 않는다.

## 5. 검색과 광고

73개 기본 페이지의 canonical 및 언어별 alternate 집합을 실제 HTML과 레지스트리에서 대조해 불일치 0건을 확인했다. 6개 하위 사이트맵에서 계산 URL 72개를 확인했고, 빠진 1개는 기존 `noindex,follow`인 생애 타임라인이다. 추천은 언어별 기본 주소를 가진 HTML 링크로 제공하고, 실제로 검색 가치가 있어 허용한 기존 결과 URL 예외를 보존한다. 출생연도 2010은 쿼리 self-canonical, 2011은 기본 canonical과 noindex였다. 학번 2025도 운영에서 쿼리 self-canonical을 확인했다. 스키마·메타·사이트맵 정책 변경은 필요하지 않다. [운영 사이트맵](https://agecalc.cloud/sitemap.xml) · [Google의 HTML 링크 지침](https://developers.google.com/search/docs/crawling-indexing/links-crawlable)

목표는 관련 페이지를 더 쉽게 발견하게 하는 것이다. 검색 영향은 Search Console의 페이지별 노출·클릭·색인 상태로 추적한다. 이번 캡처는 동의 거부·제3자 요청 차단 환경이므로 실제 광고 높이, 광고 수익, 실제 사용자의 체류 시간은 이 자료에서 추정하지 않는다.

## 6. GA4 이벤트와 판정 기준

**한국어 생일 D-day·기념일·100일·날짜 차이·하루 근무시간·주간 근무시간·세계 시간**에서는 추천 UI만 제공한다. 이들 페이지에 추적 스크립트·우회 비콘을 추가하지 않는다. 예컨대 한국어 만나이 → 생일 D-day는 출발지 클릭까지만 측정하며 도착 완료율을 ‘측정 불가’로 표시한다. 부모·자녀 페이지는 이미 GA 위치를 경로로 제한하고 Clarity를 비활성화하며 운영 응답 헤더도 `no-referrer`다. 해당 구현과 테스트를 재사용한다.

| 이벤트 | 발생 시점 | 중복 제거 |
|---|---|---|
| `calculator_completed` | 유효한 제출·조회 후 자기 계산 결과가 표시될 때. JS는 성공 렌더, SSR은 제출 표시와 성공 응답을 함께 확인 | 사용자 실행당 1회. 예시, 자동 채움, 결과 URL 직접 방문, 새로고침·뒤로 가기 제외 |
| `related_tool_impression` | 완료 후 활성 탭에서 카드 50% 이상이 연속 1초 보일 때 | 완료 건·목적지별 1회. 보이는 카드를 먼저 클릭하면 해당 노출을 클릭 직전에 1회 기록 |
| `related_tool_click` | 결과 영역의 추천 앵커를 실제로 활성화할 때 | 완료 건·목적지별 첫 활성화. 헤더·푸터·광고 제외. 분석 전송을 기다리기 위해 이동을 지연하지 않음 |
| `related_calculator_completed` | 추천을 따라 같은 탭·언어로 이동해 도착지에서 사용자가 첫 계산을 완료할 때 | 클릭 표시를 1회 소비. 연도 링크만으로 결과가 뜬 것은 클릭으로 집계하고, 도착지 직접 실행을 별도 완료로 집계 |

측정 허용 페이지와 동의한 탭에서만 입력값 없는 일회성 제출·클릭 표시를 사용한다. 목적지 도구 키·언어를 확인하고 다른 도구로 이탈하거나 30분이 지나면 폐기한다. 저장 차단·새 탭·동의 철회 시 확인 불가능한 전환은 제외한다. 동의 전 활동을 나중에 소급 전송하지 않는다. 전송 필드는 출발·도착 도구 키, 언어, 카드 순위, 배치 버전, 측정 가능 여부만 사용한다. 개인 날짜·입력 해시·사용자가 입력한 기념일 이름·전체 URL은 보내지 않는다. GA의 기본 page_view와 referrer까지 실제 요청에서 검사한다. 기존 타임라인 클릭 이벤트는 호환성을 유지하고 새 클릭 건수에 더하지 않는다.

| 지표 | 분자 / 분모 또는 비교 기준 |
|---|---|
| 추천 CTR | 같은 도구·언어·카드 순위의 노출된 카드 중 첫 클릭 수 / 노출 카드 수 |
| **완료 대비 다음 계산 실행률** | 후속 완료가 확인된 고유 출발 완료 건 / 측정 가능한 목적지가 제시된 출발 완료 건. 한 출발에서 최대 1회 성공 |
| 이동 후 실제 완료율 | 연결된 클릭 중 후속 완료 수 / 양 끝이 측정 가능하고 같은 탭으로 연결된 클릭 수 |
| 세션당 페이지 조회수·평균 참여 시간·참여율 | GA4 조회수/세션, 세션당 평균 참여 시간, 참여 세션/전체 세션. 언어·기기·결과 렌더 방식별로 확인 |

기존 링크에 같은 측정 정의를 먼저 적용해 28일 기준선을 확보한 뒤 새 배치를 적용한 28일과 비교한다. 기존에 결과 링크가 없던 도구는 카드 기준선이 없으므로 CTR과 카드 경유 완료율의 이전 값을 ‘해당 없음’으로 둔다. 이 도구들의 전후 비교에는 양쪽 기간 모두 같은 정의로 집계한 ‘계산 완료 세션 중 같은 세션에서 다른 도구까지 완료한 비율’을 보조 지표로 사용한다. 운영 반영은 별도 승인을 전제로 한다. 표본 수·측정 가능 경로 비중·동의 비중의 확인 가능한 범위와 함께 해석하고, GET 결과 재조회로 늘어난 페이지뷰를 사용자 참여 개선으로 단정하지 않는다. GA4 관리 설정·운영 전환율은 이번 검토의 실측 대상에 포함되지 않았다.

- **이번 검토의 검증 범위** — 73개 기본 페이지의 HTTP·SEO·로더 검사, 대표 결과의 운영 브라우저 확인, 최신 main의 레지스트리·다국어·지역 계산기·동의·프라이버시 기준 테스트 56개 통과. 31개 도구의 모든 입력 조합과 광고 실노출 검증은 구현 후 진행한다.
