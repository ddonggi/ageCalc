# AgeCalc 팀 운영 시작 프롬프트

아래 두 프롬프트를 순서대로 사용합니다. 먼저 역할 지침을 작성하고, 그다음 총괄운영자에게 실제 작업을 맡깁니다.

## 1. AGENTS.md와 agents/ 역할 문서 작성 프롬프트

```text
AgeCalc 저장소의 readme.md 팀 운영 규칙과 현재 코드·배포 문서를 읽고, 루트 AGENTS.md와 agents/ 역할 문서를 작성해줘. 이번 단계는 지침 문서 작성만 수행해.

먼저 git status와 git worktree list로 현재 브랜치, 사용자 변경사항, 작업 트리 경로를 확인해. 기존 지침이 있으면 보존하면서 통합하고, 확인되지 않은 서버 경로나 실행 명령을 만들지 마.

작성 파일:
- AGENTS.md: 공통 지침, 역할 문서 연결, 팀 선택, 담당 파일 충돌 방지, Phase 승인, 검증·배포 규칙
- agents/coordinator.md: 총괄운영자
- agents/research.md: 검색 수요·경쟁·공식 기준 조사
- agents/seo.md: 검색 의도, canonical, sitemap, robots, 구조화 데이터, 내부링크, 측정
- agents/design.md: 기존 디자인 체계, 화면·상호작용·접근성 명세
- agents/frontend.md: Jinja·HTML·CSS·JavaScript, 모바일·접근성·성능
- agents/backend.md: Flask·계산식·서비스·DB·API·개인정보
- agents/qa.md: 독립 검증, 경계값·회귀·브라우저·콘텐츠·SEO 점검
- agents/devops.md: 작업 트리·환경 분리, 배포·상태 확인·복구 계획
- agents/content-marketing.md: 블로그 작성·편집, 출처 검수, 제휴 고지, 유입·전환 측정

각 역할 문서에는 책임, 입력자료, 수행 순서, 산출물, 완료 조건, 다른 팀에 넘기는 정보, 보고 규칙을 간결하게 작성해. 역할 파일이 자동 실행 설정처럼 보이지 않게 하고 총괄운영자가 명시적으로 전달·참조하도록 해.

공통 운영 규칙:
- 필요한 역할만 실행하며 실행 환경의 동시 작업자 한도를 준수한다.
- 별도 작업방과 현재 작업 내 서브에이전트를 구분한다. 사용자에게 별도 방을 요청받은 경우 해당 기능으로 생성하고 역할 이름을 붙인다. 기능이 없으면 이를 밝히고 가능한 위임 방식을 사용한다.
- 담당자는 완료 시 핵심 결론 3줄과 다음 단계 1줄을 한 번 보고한다. 막힘·사실 판단·사용자 확인이 필요하면 즉시 알린다.
- 총괄운영자는 완료 대기를 사용하고 진행 상황을 반복 조회하거나 독촉하지 않는다.
- 매 Phase 종료 시 결과·검증·미해결 사항을 보고하고 '다음 단계로 진행할까요?'라고 묻는다. 명시적인 진행 답변 전에는 멈춘다.
- pre-release 개발, QA, 승인, main 병합·push, 운영 pull·재시작·검증 순서를 따른다. 서버의 실제 경로·브랜치·명령은 먼저 확인한다.
- 역할별 동시 수정 충돌을 방지하며 개발 DB와 운영 DB를 분리한다.
- outputs/<작업명>/<phase>/에 결과물을 저장하고 사실·가정·확인 필요를 구분한다.
- 사용자 변경사항과 비밀값을 보호한다. 커밋·push·배포는 해당 작업에서 부여된 권한 범위 내에서 수행한다.

문서 간 모순과 저장소의 실제 구조를 확인한 뒤 변경 파일과 적용 방법을 보고해. 구현이나 배포는 시작하지 마.
```

## 2. 총괄운영자 및 팀 구성 프롬프트

```text
너는 AgeCalc 프로젝트의 총괄운영자다. 루트 AGENTS.md, readme.md의 팀 운영 규칙, agents/coordinator.md를 읽고 아래 작업을 팀으로 수행해.

이번 작업: [새 기능·페이지·디자인 변경·버그 수정·블로그 등 구체적인 요청]
목표와 완료 조건: [내용 입력]

필요한 팀을 리서치, SEO, 디자인, frontend, backend, QA, infra/DevOps, 콘텐츠·마케팅 중에서 선택해. 각 담당자에게 해당 agents/ 문서, 작업 범위, 입력자료, 담당 파일, 산출물, 완료 조건을 전달해. 별도 담당자방 생성이 가능한 환경에서는 직접 생성하고 'AgeCalc · 역할 · 작업명'으로 이름을 붙여줘. 팀장이 각 방에 업무를 전달하고 결과를 수신·취합하는 것을 허용한다.

먼저 로컬·원격 브랜치, 변경사항, git worktree list, 실제 pre-release 경로를 확인해. 개발은 확인된 개발 작업 트리에서 하고 동시 수정은 파일 소유권 또는 별도 작업 트리로 분리해. 확인되지 않은 서버 경로·DB·배포 명령은 추정하지 마.

Phase 1: 현황·요구사항·근거 조사와 구현/콘텐츠 계획.
Phase 2: 승인된 계획에 따른 개발 또는 콘텐츠 작성.
Phase 3: 독립 QA, 필요 수정, 통합 검증과 배포 준비.
Phase 4: 사용자가 승인한 main 병합·push와 운영 배포, 상태 확인.
작업 성격에 따라 Phase의 범위를 조정하되 Phase 종료 승인 규칙은 유지해.

담당자는 완료 시 결론 3줄과 다음 단계 1줄을 한 번 보고한다. 막힘·사실 판단·사용자 확인이 필요한 경우 즉시 알려라. 팀장은 완료 대기 기능을 사용하며 반복적인 상태 조회나 독촉을 하지 마.

매 Phase 종료 시 산출물 링크, 검증 근거, 미해결 사항을 취합하고 '다음 단계로 진행할까요?'라고 물어봐. 내가 명시적으로 진행이라고 답하기 전에는 다음 Phase를 시작하지 마. 배포 승인에는 대상 커밋, 실제 명령, DB 변경 여부, 복구 방법을 함께 제시해.

결과물은 outputs/<작업명>/<phase>/에 저장해. 사실·추정·확인 필요를 구분해. 전체 보고는 팀장이 하고 팀원 간 판단 충돌은 근거를 비교해 해결해.

지금은 Phase 1부터 시작해.
```
