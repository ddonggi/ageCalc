# AgeCalc Editorial Luxury 전체 테마 개편 설계

## 목표

AgeCalc의 계산 기능, URL, 검색 노출 구조를 유지하면서 사이트 전체를 따뜻하고 정교한 Editorial Luxury 디자인으로 통일한다. 홈, 계산기, 생활 허브, 블로그, 가이드, 표, 정책 페이지가 하나의 브랜드 경험으로 연결되어야 한다. 기존 범용 미니게임은 삭제하지 않고 공개 탐색과 검색 색인에서 제외하며, 추후 나이·날짜·생애주기와 관련된 게임으로 교체할 수 있도록 보관한다.

## 범위

### 포함

- 공용 색상, 타이포그래피, 간격, 반경, 표면, 모션 토큰
- 공용 헤더, 모바일 내비게이션, 푸터, 버튼, 폼, 결과 요약, 빠른 링크
- 홈 화면의 핵심 계산 흐름과 생활 영역 탐색
- 모든 계산기 페이지의 입력·결과·해석 구조
- 블로그, 가이드, 표, 정책, 문의 페이지의 편집형 레이아웃
- 기존 범용 미니게임의 공개 노출 및 검색 색인 차단
- 반응형, 접근성, SEO, 성능 및 계산 결과 회귀 검증

### 제외

- 계산 공식과 결과 산출 로직 변경
- Flask 또는 Jinja에서 다른 프레임워크로의 이전
- 기존 미니게임 코드와 정적 자산 삭제
- 새로운 관련 게임의 기획 또는 구현
- URL 체계의 전면 변경

## 시각 방향

선택한 방향은 `high-end-visual-design`의 Editorial Luxury 계열이다. 고급 편집물의 여백과 타이포그래피를 사용하되, 계산 도구로서의 명확성과 속도를 우선한다.

### 디자인 원칙

1. 브랜드 표현과 기능을 분리하지 않는다. 계산 패널 자체가 대표 시각 요소가 된다.
2. 색상은 크림, 에스프레소, 세이지를 중심으로 제한한다.
3. 한글 정보는 선명한 고딕으로 제공하고, 영문 브랜드와 장식적 대형 제목에만 세리프를 사용한다.
4. 카드 남용을 피하고 여백, 구분선, 크기 대비로 계층을 만든다.
5. 겹침과 깊이감은 데스크톱의 핵심 장면에만 사용하고 모바일에서는 단일 열로 단순화한다.
6. 모션은 의미 있는 진입, 포커스, 클릭 피드백에만 사용한다.

## 디자인 토큰

### 색상

| 역할 | 값 | 용도 |
| --- | --- | --- |
| 배경 | `#F6F1E8` | 전체 캔버스 |
| 주요 표면 | `#FCF9F3` | 밝은 패널과 콘텐츠 영역 |
| 핵심 패널 | `#241D18` | 대표 계산기와 강조 영역 |
| 본문 | `#29231F` | 기본 텍스트 |
| 보조 글자 | `#746B63` | 설명, 메타 정보 |
| 주요 포인트 | `#66705A` | 핵심 CTA와 선택 상태 |
| 보조 장식 | `#A68B61` | 얇은 선과 제한적 장식 |
| 오류·경고 | `#A34C3D` | 검증 오류와 경고 |

주요 행동에는 세이지 한 색만 사용한다. 앤티크 골드는 텍스트 링크의 기본색이나 큰 면적 배경으로 사용하지 않는다.

### 글꼴

- 영문 브랜드와 장식적 대형 제목: `Cormorant Garamond`
- 한글 제목과 본문: `Pretendard`
- 날짜와 계산 결과: `IBM Plex Mono`
- 외부 폰트 실패 시 한국어 시스템 글꼴과 범용 serif, monospace 대체 스택을 제공한다.
- 수치에는 `font-variant-numeric: tabular-nums`를 적용한다.
- 본문 줄 길이는 약 65자로 제한하고 줄 높이는 최소 1.6으로 유지한다.

### 형태와 표면

- 일반 컴포넌트 반경은 8~14px 범위로 제한한다.
- 대표 계산 패널은 바깥 프레임과 안쪽 코어의 이중 구조를 사용한다.
- 그림자는 배경색에 맞춘 낮은 불투명도의 확산형 그림자만 사용한다.
- 종이 질감은 고정된 저불투명도 오버레이 한 겹으로 구현하고 콘텐츠 스크롤 컨테이너에는 필터를 적용하지 않는다.

### 모션

- 진입 효과는 `transform`과 `opacity`만 사용한다.
- 기본 지속 시간은 200~700ms 범위이며 사용자 행동 피드백이 가장 짧다.
- 스크롤 기반 진입이 필요하면 `IntersectionObserver`를 사용한다.
- `prefers-reduced-motion: reduce`에서는 비필수 모션을 제거한다.

## 공용 컴포넌트

### 헤더와 내비게이션

- 데스크톱에서는 콘텐츠 상단에서 살짝 떨어진 밝은 플로팅 바를 사용한다.
- 로고, 주요 생활 허브, 블로그, 모바일 메뉴 순으로 명확한 탐색 계층을 유지한다.
- 현재 위치와 키보드 포커스를 색상 외에도 밑줄 또는 선으로 표시한다.
- 모바일 메뉴는 단일 열의 전체 탐색 패널로 유지하고 배경 스크롤과 포커스 이동을 관리한다.

### 계산 패널

- 필드 라벨은 입력 위에 둔다.
- 기본, 포커스, 입력 완료, 오류, 비활성 상태를 각각 정의한다.
- 핵심 CTA는 세이지 배경과 밝은 텍스트를 사용한다.
- 결과는 큰 숫자, 단위, 보조 설명이 분리된 요약 영역에 표시한다.
- 계산 전에는 빈 숫자를 결과처럼 보이지 않게 안내 상태를 제공한다.
- 오류 메시지는 해당 필드 아래에 표시하며 `window.alert()`를 사용하지 않는다.

### 링크와 콘텐츠

- 빠른 계산 링크는 동일한 카드의 반복보다 얇은 구획선이 있는 가로 목록 또는 비대칭 그리드를 사용한다.
- 주요 버튼 하나를 제외한 보조 행동은 텍스트 링크나 낮은 강조 버튼으로 제공한다.
- 광고와 제휴 콘텐츠는 라벨, 배경, 간격으로 편집 콘텐츠와 명확히 구분한다.

## 페이지별 설계

### 홈

- 왼쪽에 브랜드 메시지와 서비스 설명, 오른쪽에 즉시 사용할 수 있는 만나이 계산기를 배치한다.
- 데스크톱에서는 계산 패널을 종이 또는 달력 판이 겹친 것처럼 표현한다.
- 모바일에서는 장식적 겹침을 제거하고 설명, 입력, 결과 순서로 쌓는다.
- 첫 화면 아래에 학년, 생일, 아이 개월수, 반려동물 등 빠른 계산 경로를 제공한다.
- 생애 타임라인과 생활 영역 허브는 편집형 섹션으로 연결한다.

### 계산기

모든 계산기 페이지를 다음 흐름으로 통일한다.

1. 계산기의 목적과 기준
2. 입력 폼
3. 계산 결과
4. 결과 해석과 예외
5. 관련 표, 가이드, 다른 계산기로 이동

기존 JavaScript 계산 로직과 서버 데이터 계약은 유지한다. 스타일 변경 때문에 필드의 이름, ID, 이벤트 연결이 깨지지 않아야 한다.

### 블로그와 가이드

- 목록은 표지 이미지와 제목이 교차하는 편집형 구성을 사용한다.
- 본문 폭, 제목 크기, 발행 정보, 참고 출처, 관련 계산기 경로를 일관되게 제공한다.
- 광고와 제휴 영역은 본문 문단처럼 오인되지 않도록 분리한다.
- 읽기 진행률, 목차, 관련 글 등 현재 기능은 새 시각 시스템에 맞게 재표현하되 동작은 유지한다.

### 표, 정책, 문의

- 큰 데이터 표에는 고정된 숫자 정렬, 충분한 행 간격, 모바일 가로 스크롤 안내를 제공한다.
- 정책과 문의 페이지는 장식보다 읽기 폭과 제목 계층을 우선한다.
- 공용 헤더와 푸터를 사용해 보조 페이지가 별도 사이트처럼 보이지 않게 한다.

## 미니게임 보관 정책

- 홈, 헤더, 푸터, 관련 경로, 콘텐츠 추천에서 기존 범용 미니게임 링크를 제거한다.
- 공개 사이트맵에서 게임 허브와 개별 게임 URL을 제외한다.
- 게임 페이지에는 `noindex, nofollow`를 적용한다.
- 기존 라우트, 템플릿, JavaScript, CSS, 이미지 자산은 삭제하지 않는다.
- 기존 URL에 직접 접근하는 사용자는 페이지를 계속 이용할 수 있다.
- 향후 관련 게임이 준비되면 기존 게임 허브 경로를 AgeCalc 전용 게임 탐색 화면으로 교체한다.

## 기술 접근

- Flask, Jinja, vanilla CSS와 현재 JavaScript 구조를 유지한다.
- `static/css/style.css`의 기존 토큰과 공용 선택자를 새 시스템으로 단계적으로 교체한다.
- 반복되는 헤더, 푸터, 광고, 편집 메타, 관련 경로는 기존 partial을 확장한다.
- 페이지마다 독립 HTML 문서가 존재하므로 공용 변경과 대표 페이지 변경을 분리해 회귀 범위를 관리한다.
- 게임별 CSS는 보관하며 공용 테마 변경으로 게임 보드가 깨지지 않도록 게임 페이지의 범위를 격리한다.
- 새 라이브러리는 원칙적으로 도입하지 않는다. CSS와 현재 JavaScript로 구현하기 어려운 요구가 생길 때만 별도 승인을 받는다.

## 접근성 및 오류 처리

- 본문과 컨트롤은 WCAG AA 명암 대비를 충족한다.
- 모든 인터랙티브 요소에 키보드로 식별 가능한 포커스 표시를 제공한다.
- 메뉴와 대화형 패널의 `aria-expanded`, `aria-controls`, `hidden` 상태를 유지한다.
- 계산 오류는 입력 필드와 연결된 인라인 문구로 설명한다.
- 이미지에는 의미에 맞는 대체 텍스트를 제공하며 순수 장식 이미지는 보조 기술에서 숨긴다.
- 최소 44×44px 터치 영역을 확보한다.

## 검증 전략

### 기능 회귀

- 만나이, 학년, 생일 D-day, 아이 개월수, 반려동물 나이의 대표 입력과 경계값을 검증한다.
- 폼 ID, 이름, 이벤트 연결, 결과 출력 위치가 유지되는지 확인한다.
- 모바일 메뉴, 쿠키 동의, 읽기 진행률, 관련 링크가 정상 동작하는지 확인한다.

### 시각·반응형 검증

- 홈, 대표 계산기, 블로그 목록·본문, 가이드, 표, 정책 페이지를 기준 화면으로 사용한다.
- 데스크톱, 태블릿, 좁은 모바일에서 오버플로, 겹침, 잘림, 지나치게 긴 줄을 확인한다.
- 게임 URL 직접 접근 시 공용 테마가 게임 보드를 침범하지 않는지 확인한다.

### SEO·성능 검증

- 기존 `title`, description, canonical, Open Graph 정보가 유지되는지 확인한다.
- 사이트맵에서 기존 게임 URL이 제거되고 다른 공개 URL이 누락되지 않는지 확인한다.
- 게임 페이지의 robots 지시문을 확인한다.
- 폰트 로딩, 레이아웃 이동, 이미지 크기, 애니메이션 비용을 측정한다.
- Core Web Vitals 기준을 훼손하는 대형 이미지, 과도한 blur, 연속 스크롤 이벤트를 허용하지 않는다.

## 완료 조건

- 모든 공개 페이지가 동일한 Editorial Luxury 디자인 토큰과 공용 컴포넌트를 사용한다.
- 핵심 계산 기능과 기존 공개 URL이 유지된다.
- 대표 페이지가 데스크톱과 모바일에서 의도한 계층과 사용 흐름을 제공한다.
- 키보드 탐색, 포커스, 명암 대비, 오류 안내가 검증된다.
- 기존 미니게임은 코드 삭제 없이 공개 탐색과 검색 색인에서 제외된다.
- 자동화 테스트와 수동 시각 검증에서 치명적 회귀가 없다.
