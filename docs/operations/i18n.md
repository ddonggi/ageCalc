# Multilingual calculators

The implementation was started on `c81bd94` and rebased onto `origin/main` at `e952128` on 2026-09-10. Korean age calculation stays at `/age`; `/age-calculator` is not introduced as a Korean alias. Existing Korean pages retain their content, calculations, forms, advertising rules and canonical paths, including the latest upstream fixes.

## Public pages and resources

Six calculators have English, Japanese, Spanish, Brazilian Portuguese and Simplified Chinese equivalents: age, birthday countdown, days until/since, baby months, the 100th day and birth-year difference. They add 30 URLs. Foreign slugs match Korean slugs except `/age`, whose foreign slug is `age-calculator`.

- `content/locale_config.py`: URL prefixes, hreflang/HTML codes, Intl locales, date field order and cultural feature defaults.
- `content/page_registry.py`: the existing page registry plus supported locales and foreign template/slug settings. Other pages default to Korean only.
- `content/i18n.py`: catalog loading/validation, explicit route registration, language links, SSR metadata and sitemap expansion.
- `translations/*.json`: common UI and each supported foreign page's complete editorial copy. Korean legacy content remains in its original templates; `ko.json` owns the new language-switcher label.
- `templates/partials/global-calculator.html`: shared foreign layout and forms, selected from each existing calculator template. The six Korean template bodies remain intact.
- `static/js/global-calculations.js`: pure locale-independent calendar operations that reuse existing date rules.
- `static/js/global-calculator.js`: private browser input handling and localized formatting. It makes no network or storage calls.

Catalogs are validated when routes are registered. Missing supported page translations, empty required text, mismatched placeholders, unsupported locales and duplicate paths fail startup rather than silently serving mixed-language documents. Restart workers after updating catalogs; they are cached per process.

To add a language, add its behavior configuration and complete common/page resources, then add it to the intended pages' supported locale sets. A page may support a subset of languages and need not have an English version. Page-specific content and routes, not browser settings or cookies, determine language. The initial six pages currently opt into all configured locales through `ALL_LOCALES`; change this per page when introducing a partial language rollout.

The registry's `_page` builder accepts `locales`, `culture` and `locale_features` overrides. For example, `locales=('ko', 'en')` limits a page to those two versions, and `locale_features={'en': {'year_age': True}}` overrides an English feature for that page only. A translated content section can specify a `feature` key to conditionally display it. Its default layout remains shared.

The brand links to the same-language age calculator when available, otherwise to the current supported calculator. A partial rollout does not depend on having a translated age calculator.

## Consistent language navigation

The UX follow-up keeps the existing URL and content architecture, with three changes:

1. Show the current language in the shared header on the Korean home, Korean-only pages and translated tools, retaining Korean in the list.
2. Prefer an equivalent page. If unavailable, explain the fallback and open that language's age calculator (or another supported calculator if age is unavailable). Unregistered Korean pages return to `/` when choosing Korean. Switching never carries private query inputs.
3. Share a small dedicated stylesheet and native `details` menu across layouts, with Escape, outside-click and focus-leaving dismissal. Links work without JavaScript. Mobile menus align with the header actions to fit narrow screens.

`navigation_language_links` supplies these UI links. `language_links` remains reserved for real SEO equivalents; a fallback does not add hreflang or sitemap entries, nor change canonical URLs. This does not create translated home pages. The shared menu loads versioned `language-switcher.css` and `language-switcher.js`; Korean pages no longer load the global calculator layout stylesheet.

`tests/language-navigation.cjs` checks home, Korean-only, blog and translated pages at 320, 375 and 1280 pixels, plus keyboard/outside-click dismissal and navigation with JavaScript disabled. Its default local server is `http://127.0.0.1:8000`.

## Calendar and privacy contracts

Global pages render title, description, headings, instructions, examples, FAQs, field labels and metadata in the requested language before JavaScript runs. JavaScript only enables the calculator and displays its results. With JavaScript disabled or initialization failing, inputs remain disabled and a localized explanation remains visible; language links still work.

Dates are Gregorian date-only values. Today uses the device's local date at calculation time, and date differences use UTC calendar days to avoid DST effects. Visible field order is independent of ISO/model order. Month names, result dates and plural units are localized.

- Completed years use the existing birthday comparison, including March 1 for February 29 birthdays in common years.
- Monthly anniversaries clamp to a shorter month's last day. January 31 to February 28 is one completed month. Completed months are an independent measure, not necessarily `completed years × 12 + remainder` around leap birthdays.
- Detailed age uses completed years, up to 11 further original-date monthly anniversaries, and remaining days. The zero-month anniversary retains the March 1 yearly convention.
- Birthday countdowns target the next literal birthday date, including the next actual February 29.
- The 100th day includes the start as day 1 and adds 99 days.
- Birth-year difference is an absolute difference between years, not an exact age gap.

Inputs do not enter request parameters, URLs, local/session storage or analytics events. Form and result regions retain Clarity masking. Links switch language without preserving private input. No new sharing, profile persistence or feedback endpoint is added. Existing Korean browser/server month-rule differences are deliberately preserved.

## SEO and operating compatibility

Every supported document has its own canonical and OG URL and all six reciprocal hreflang links. No `x-default` is emitted. Unavailable foreign page combinations return 404. Foreign trailing slashes redirect once to the clean path. The existing Korean `/age/` legacy hub redirect remains unchanged.

The sitemap keeps its index and groups, adding only supported variants of already indexable pages. The review-mode baseline is 44 Korean URLs plus 30 foreign URLs. The former test expectation of 46 Korean URLs predates HEAD's two school-page consolidations. `tests/i18n_expected.py` records the independent Korean URL baseline to catch accidental removals.

Existing AdSense, analytics consent, Google/Naver verification and robots settings are reused. Foreign pages omit Korean promotions, donation widgets and policy sections. Footer policy/about/contact destinations remain Korean and are marked as such. Global WebPage and BreadcrumbList schemas describe the visible localized document; the age calculator also keeps localized SoftwareApplication and FAQPage types. No Korean reviewer/source assertions are copied into global copy.

Nginx already forwards prefixed paths to Flask. New assets use the project's content-hash URLs because production static assets have long-lived caching. The existing Korean quality-audit script selects the legacy Korean registry; foreign page coverage is supplied by the i18n integration/browser checks, not by claiming those Korean editorial checks audit all 74 documents.
