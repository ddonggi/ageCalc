# AgeCalc 자체 데이터 공개·인용 정책

기준일: 2026-08-16

이 문서는 AgeCalc가 향후 자체 이용 통계를 공개할 때 적용할 최소 기준이다. 이번 작업은 정책과 검증 형식만 정의하며 이벤트 추가, 데이터 수집, 공개 페이지 게시, 개인정보처리방침 변경을 수행하지 않는다.

## 현재 상태와 허용 출처

- GA4 `page_view`: 분석 쿠키에 동의한 사용자에 한해 현재 수집될 수 있다. 입력값과 계산 결과는 통계 차원으로 사용하지 않는다.
- `page_feedback` DB: 페이지 경로, 도움됨/도움안됨 선택, 생성 시각만 저장하는 기존 익명 피드백이다. 개발 DB의 현재 표본은 0건이므로 공개 수치가 없다.
- 계획 이벤트: 계산 시작·완료, 입력 오류 코드, 관련 도구 클릭은 후보일 뿐이며 아직 구현하거나 수집하지 않는다. 구현 시에도 GA4 동의 이후에만 전송한다.

서버 로그는 보안·장애 대응 자료이고 IP 및 user-agent가 포함될 수 있어 공개 통계 원천에서 제외한다. Microsoft Clarity는 정성적 UX 진단용이므로 대표 통계에 사용하지 않는다. 블로그·RSS DB도 계산 도구 이용 통계의 출처로 사용하지 않는다.

## 수집 금지 값

생년월일·출생연도·계산된 나이·학년·학번·기념일 날짜와 이름·가족 관계·반려동물 나이 등 사용자의 입력값과 결과값을 이벤트에 담지 않는다. 쿼리 문자열, IP 주소, user-agent, 사용자·세션 식별자, 개별 이벤트 시각도 공개 집계 차원으로 사용하지 않는다.

허용 차원은 월, canonical 경로 또는 사전에 정의한 도구 키, 값이 없는 오류 코드, 출발·도착 도구 키, 피드백 선택처럼 개인을 재식별할 수 없는 범주로 제한한다. 정확한 허용 목록은 `metric-catalog.json`을 단일 기준으로 삼는다.

## 공개 후보 지표와 산식

- 월별 도구 관심도: 특정 도구의 동의 사용자 page view ÷ 공개 대상 도구 전체의 동의 사용자 page view × 100
- 계산 완료율: 계산 완료 이벤트 ÷ 계산 시작 이벤트 × 100
- 입력 오류율: 입력 검증 오류 이벤트 ÷ 계산 시작 이벤트 × 100
- 도움됨 비율: 도움됨 응답 수 ÷ 전체 피드백 응답 수 × 100
- 관련 도구 이동률: 관련 도구 클릭 이벤트 ÷ 해당 출발 도구 page view × 100

계산 이벤트 후보는 실제 구현 이후에만 지표 계산에 사용할 수 있다. 현재 값은 만들거나 추정하지 않는다.

## 공개 기준과 소수 표본 보호

지표 하나를 공개하려면 분모가 100 이상이고 관찰 기간이 연속 28일 이상이어야 한다. 세부 범주별 셀이 20건 미만이면 해당 셀은 숨기거나 상위 범주로 합친다. 조건을 충족하지 못하면 0으로 표시하지 않고 “표본 부족”으로 처리한다.

모든 공개 표에는 지표명, 값과 단위, 기간 시작·종료일, 분모 표본 수, 출처, 산식, 포괄 범위와 편향, 최종 갱신일을 기록한다. 백분율만 공개하지 않고 분모를 함께 제공한다.

## 보존과 편향 고지

식별자가 없는 월별 집계는 비교 분석을 위해 14개월 보존한다. 기존 `page_feedback` 원시 행은 12개월 후 삭제하는 정책을 적용하되, 실제 삭제 작업은 별도 구현·검증 항목으로 진행한다.

GA4 수치는 분석 쿠키 동의자만 포함하므로 전체 이용자를 대표하지 않는다. 피드백은 자발적 응답자만 참여하는 자기선택 편향이 있다. 봇 필터, 광고·추적 차단, 중복 방문, 이벤트 누락으로 수치가 달라질 수 있음을 표마다 고지한다. 인과관계나 전체 사용자 선호로 확대 해석하지 않는다.

## 공개 절차

1. 승인된 출처에서 월 단위 익명 집계만 추출한다.
2. `scripts/validate_owned_data_catalog.py`로 카탈로그 계약을 검증한다.
3. 분모·기간 기준과 20건 미만 셀 억제를 적용한다.
4. 담당자가 산식, 기간, 표본 수, 편향 문구를 원자료 집계와 대조한다.
5. `citation-table-template.csv` 형식으로 기록하고 공개 여부를 별도 승인한다.
6. 공개 후 출처와 최종 갱신일을 유지하며 산식 변경 이력을 남긴다.

향후 이벤트를 실제로 추가하거나 보존·삭제 방식을 바꿀 때는 개인정보처리방침과 동의 흐름을 다시 검토한다. 이 정책 자체는 수집 또는 공개 승인이 아니다.
